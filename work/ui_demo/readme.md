# 界面可视化编辑说明

本文说明 Qt Designer 怎么用，以及在这个项目里怎么用它调整界面。

本项目选定的方式是**丙：Designer 当草稿纸，不接入程序**。你在 Designer 里拖，
拖完把 `.ui` 或截图交给开发者，由开发者落到代码里。这样你能可视化地调，代码仍
然是唯一的真相，不会出现两套东西对不上的情况。

## 一、日常三步

**第一步，打开草稿纸。** 双击本目录的 `open-designer.bat`，或者用 Designer 打开
`pages\search.ui`（检索页）、`pages\library.ui`（图库页）、`pages\settings.ui`
（设置页）、`pages\card.ui`（单张结果卡片）。

**第二步，拖。** 想直接看效果按 `Ctrl+R` 预览，不需要保存，也不需要跑程序。
调界面的大部分时间应该花在预览上。

**第三步，交回。** 保存 `.ui`，把文件或截图发给开发者。想自己先看运行时的样子：

```powershell
python work\ui_demo\run_demo.py pages\search.ui
```

**草稿纸要换新。** `pages\` 下的文件是从当时的真实界面导出来的。开发者改过界面
之后会重跑一次导出，你手上那份要换最新的，否则你在拖的是旧版。

## 二、Designer 在哪，怎么开

PySide6 自带，已经装在本机：

```
C:\PYthon313\Scripts\pyside6-designer.exe
```

| 方式 | 做法 |
|---|---|
| 双击 | 本目录的 `open-designer.bat` |
| 命令行 | `pyside6-designer work\ui_demo\pages\search.ui` |
| 空白起步 | `pyside6-designer`，会问建什么，选 **Widget** |

它不注册开始菜单项，只能按路径找。不带文件名启动时，做这类带布局的页面一律选
**Widget**，不要选 Main Window 或 Dialog。

## 三、Designer 的四个区域

| 区域 | 位置 | 用途 |
|---|---|---|
| 控件箱 | 左侧 | 拖控件用。常用的是 Layouts、Spacers、Buttons、Input Widgets、Display Widgets 五组 |
| 对象查看器 | 右上 | 显示控件树。**这是最重要的面板**，层级错了布局就错 |
| 属性编辑器 | 右下 | 改当前选中控件的属性。`objectName`、`text`、`placeholderText`、`checked`、`styleSheet`、`sizePolicy` 都在这里 |
| 信号与槽编辑器 | 右下第二个页签 | 简单的连接可以在这里点出来。**我们不用它**，见第六节 |

改动布局的三个常用手段：拖控件换位置、把控件拖进或拖出容器、在控件之间插
Spacer 撑开。**Spacer 是最容易被忽视的一个**，右侧那些空白大多靠它，不是靠固定宽度。

## 四、草稿纸从哪来

`pages\` 下的 `.ui` 不是照着画的，是程序自己导出来的：

```powershell
python work\ui_demo\dump_ui.py
```

它启动一次真实界面，把控件树、文案、间距、对齐、下拉框候选项全部写进 `.ui`，
同时存一张真实界面的截图（`pages\*.png`）供对照。因此在 Designer 里看到的就是
程序里真实的样子。

导出有四条已知偏差，都是刻意的：

| 偏差 | 说明 |
|---|---|
| 隐藏控件会显示出来 | 进度条、取消、重试、卡片角标在程序里默认不可见。不显示出来，改版时容易漏掉 |
| 缩略图位置显示「加载中」 | 草稿纸里没有真图 |
| 结果卡片没有 | 结果卡片是检索完成才建的，空白状态下不存在 |
| 自定义控件变成空白区域 | 结果图墙与卡片是自定义类，Designer 不认识。卡片已单独导成 `card.ui` |

### 标签区里的按钮是示例，不是固定结构

标签按钮本来也是「检索之后才有」的那一类。导出脚本现在默认先按「真机伶」翻一次，
好让你在草稿纸里直接看到新样式与那两行网格。**但那些按钮是示例内容**：

- 按钮个数由你输入什么词决定，程序里是按候选数量动态生成的，不是四个或五个写死的。
- 按钮上的序号、文字与绿底是运行时算出来的。绿底的含义是「这个标签会进检索式」，
  由设置页的标签数上限决定。
- 因此**你要调的是外面那个滚动区容器**（高度、边框、位置），以及说明文字的位置。
  不要去删或挪单个按钮——它们下次导出会重新生成。
- 想看干净的空状态，用 `--translate ""` 再导一次。

三个页面的其余部分都是静态骨架，随便拖。

## 五、Designer 做不了的事

这一节是「为什么不能把整个界面搬进 Designer」的答案。

| 做不到 | 本项目里的例子 |
|---|---|
| 按数据循环生成控件 | 类别按钮、来源勾选、标签按钮都是运行时按数据建的。Designer 里只能摆一个，摆不出 N 个 |
| 结果图墙 | 196 张卡片是运行时建的，还要异步加载缩略图 |
| 复杂的信号连接 | 检索、下载、重试、取消都要跨线程，信号槽在代码里接 |
| 集中在代码里的样式 | 当前样式散在各处的 `setStyleSheet`，例如灰色提示、标签底色、错误红字。Designer 的 `styleSheet` 属性只是同一个字符串，改不出集中管理 |

一句总结：**Designer 管的是静态骨架，也就是一次摆好就不动的行与组。** 检索页有
七行控件，其中四行属于这一类。

## 六、附：.ui 接进程序的两条路

本期不走这两条路，记在这里是为了将来真要改架构时不用重新查。

`.ui` 是一份 XML，Qt 不能直接执行。**路一，运行时读**，`run_demo.py` 用的就是它：

```python
from PySide6.QtUiTools import QUiLoader

loader = QUiLoader()
window = loader.load("pages/search.ui")
button = window.findChild(QPushButton, "translateButton")   # 按名字取控件
```

这样加载的控件没有对应的 Python 类。**最容易踩的坑是名字对不上不报错**：
`findChild` 找不到就返回 `None`，按钮点了没反应，界面上看不出任何异常。

**路二，编译成 Python**，控件变成属性，编辑器能自动补全，取错了当场报错：

```powershell
pyside6-uic work\ui_demo\pages\search.ui -o work\ui_demo\ui_search.py
```

代价是多一步生成，生成的文件不能手改。

## 七、三条路，以及为什么选丙

| | 做法 | 成本 | 你能自己拖吗 |
|---|---|---|---|
| 甲 | 完全不动，你提意见开发者改代码 | 最低 | 不能 |
| **丙** | **Designer 只当草稿纸，不接入程序** | **零风险，随时可开始** | **能，改完交给开发者落地** |
| 乙 | 静态骨架搬进 `.ui`，动态部分留代码 | 重构三个页面并重跑打包与验证 | 能，改完重跑就见效 |

**已选丙。** 理由是先摸清想要什么，再决定值不值得为长期的可视化控制权付一次重构。
将来若确认界面要反复调，再走乙。

不建议第四条路：把界面全部搬进 `.ui`。动态生成那几块永远搬不过去，结果是改一个
界面要在两个地方找，对不熟悉 Qt 的人最容易迷路。

## 八、本目录的文件

| 文件 | 用途 |
|---|---|
| `pages\search.ui` 等四个 | **从真实界面导出**的草稿纸，要调界面就用这些 |
| `pages\*.png` | 导出那一刻的真实界面截图，用来核对导出的 `.ui` 有没有走样 |
| `pages\dump-report.txt` | 每次导出的记录：数据目录、窗口尺寸、各页尺寸 |
| `search_top.ui` | 手写的入门小例子，只有检索页的前五行，适合先看懂结构 |
| `dump_ui.py` | 导出脚本，见第四节。带 `--translate 词` 可以指定标签区的示例候选 |
| `run_demo.py` | 运行时加载 `.ui` 的示例，带 `--shot` 可以把界面存成图片 |
| `open-designer.bat` | 双击打开 Designer 并加载草稿纸 |
| `readme.md` | 本文 |
| `_data\` | 导出脚本用的临时数据目录，约 10 MB，删掉会自动重建 |

草稿纸**不接入程序**，随便拖。改坏了重跑一次 `dump_ui.py` 就还原了。

`open-designer.bat` 只含 ASCII 字符，原因与 `installer` 下的脚本相同：cmd 用系统
代码页读没有字节顺序标记的批处理文件，写中文会乱码。中文说明一律放本文。
