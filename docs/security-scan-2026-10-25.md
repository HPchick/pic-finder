# 上传前敏感信息检查

检查日期：2026 年 10 月 25 日。
上传范围：工作区 `picfinder/` 仓库的源码、词表与文档。

## 检查方法

上传前按 Git 待提交清单建立隔离副本。
使用 Gitleaks 8.30.1 扫描全部候选内容。
补充检查私钥、带密码的连接地址和常见令牌格式。
人工复核源码、测试值和历史文档中的凭据字段。
提交前再次扫描 Git 暂存区中的实际文件内容。

扫描器仅在本机读取文件，不上传待查内容。
工具来自官方发布页，下载后核对 SHA-256。
扫描副本、工具与详细报告保存于本地材料目录。
该目录为 `.local-work/2026-10-25/`，由 Git 忽略。

## 检查结果

初次扫描覆盖 144 个候选文件，约 11 MiB。
Gitleaks 和补充规则均未检出凭据。
人工检查未发现真实密码、密钥、令牌或登录 Cookie。
提交前的最终数量与摘要以本地扫描清单为准。

测试中的空 key、中文占位值及全零假 key 均非实际凭据。
社区画师词表中的邮箱和数字样式属于标签或别名。
它们不属于本项目的登录配置。

以下内容不参与提交：

- `.env`、运行配置与本机目录指针。
- 用户数据库、图片库、日志与缓存。
- 本地备份、验证副本及扫描工具。
- 构建目录、便携压缩包及安装程序。

公开文档保留匿名访谈、开发记录及本机路径。
这些内容不包含认证秘密。
本次扫描结果不是对全部潜在泄露的绝对保证。

## 后续凭据管理

真实凭据只写入本机配置或专用凭据存储。
示例配置使用空值或明确占位值。
提交前检查暂存区，避免整批加入运行数据。
`.gitignore` 无法移除已被 Git 跟踪的文件。

误传密码或令牌后，先撤销或轮换凭据。
只删除最新文件无法清除提交历史中的旧值。
处理方法见 [GitHub 官方说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)。

Gitleaks 的规则与局限见[官方仓库](https://github.com/gitleaks/gitleaks)。
