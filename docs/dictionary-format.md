# 词典文件格式

本文定义 PIC FINDER 本地词典的文件格式、加载规则与维护流程。本文解决 OQ-04 的词典冷启动策略。

词典是 DD-04 所述翻译层的离线部分。它必须满足四条要求。

1. **离线可用。** 未配置接口时软件仍能翻译常见词汇。
2. **可增量更新。** 新词可以随时补充，不需要重写整个文件。
3. **可被用户覆盖。** 用户改过的词在词典升级后仍然有效。
4. **按四类分开组织。** DD-18 已确认词典需要按参考图类别分别组织，因为各类的术语体系不同。

## 数据分三层

处理顺序自下而上，下层不修改上层文件。

| 层 | 存放位置 | 谁写 | 会不会被升级覆盖 |
|---|---|---|---|
| 内置词典 | `data/dictionary/*.json` | 开发与词典构建流程 | 会，随程序升级替换 |
| 词典缓存 | 数据库 `dictionary_entry` 表 | 程序启动时从文件加载 | 会，每次加载重建 |
| 用户覆盖 | 数据库 `dictionary_override` 表 | 用户在界面上操作 | 不会 |

**关键约束：用户的修改只写第三层。** 这样词典文件随程序升级替换时，用户的修改不会丢。这是把用户覆盖单独建表的唯一理由。

### common 不是第五个类别

词典文件有 `common.json`，但 `common` 只用于**组织词典文件**，它不是参考图的类别。参考图的一级分类是 DD-18 认定的四类，数据库的 `content_category` 表里也只有这四类。

因此加载时 `common` 类别的词条写入数据库时 `content_category_id` 为 **NULL**，语义是「四类通用」。查询某个类别的词典时，取该类别自身与 NULL 两组。

这样处理有两个好处。第一，不引入第五个类别，与 DD-18 一致。第二，通用词只有一份，不必在四个类别里各存一份并保持同步。

**实现注意：** 在 SQLite 中 NULL 互不相等，因此 `UNIQUE (content_category_id, term_zh, tag)` 无法阻止同一通用词被写入多次。写入层必须先按唯一键探测是否存在，不能只依赖约束。

## 文件清单

词典按类别拆成多个文件，另加一个全局文件。

| 文件 | 内容 |
|---|---|
| `manifest.json` | 词典清单，记录版本与各文件校验值 |
| `common.json` | 四类通用的词汇，例如画质与构图类描述 |
| `pose.json` | 人体姿势类 |
| `outfit.json` | 服装类 |
| `prop.json` | 道具类 |
| `scene.json` | 场景建筑类 |

拆分的理由有三条。人体姿势类词汇量最大，单独一个文件便于分工；四类的术语体系不同，混在一个文件里容易互相污染；单文件改动不会影响其他类的校验值。

## 单个词典文件的结构

以 `pose.json` 为例。

```json
{
  "schema_version": 1,
  "category": "pose",
  "dictionary_version": "2026.10.1",
  "generated_by": "builtin",
  "reviewed": true,
  "entries": [
    {
      "term": "站姿",
      "tags": [
        { "tag": "standing", "weight": 1.0 },
        { "tag": "full_body", "weight": 0.4 }
      ],
      "exclude": ["sitting", "lying"],
      "notes": "站立全身。full_body 是辅助标签，权重低。"
    },
    {
      "term": "侧身",
      "tags": [
        { "tag": "from_side", "weight": 1.0 }
      ],
      "exclude": [],
      "notes": ""
    },
    {
      "term": "回眸",
      "tags": [
        { "tag": "looking_back", "weight": 1.0 }
      ],
      "notes": "画师常用说法，对应 Danbooru 的 looking_back。"
    },
    {
      "term": "坐",
      "tags": [
        { "tag": "sitting", "weight": 1.0 }
      ],
      "aliases": ["坐着", "坐姿"]
    },
    {
      "term": "跪",
      "tags": [
        { "tag": "kneeling", "weight": 1.0 }
      ],
      "aliases": ["跪姿", "跪着"]
    }
  ]
}
```

## 字段规范

### 文件级字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `schema_version` | 整数 | 是 | 格式版本。格式变更时递增，程序据此决定是否兼容 |
| `category` | 字符串 | 是 | 类别标识，取值 `common`、`pose`、`outfit`、`prop`、`scene` |
| `dictionary_version` | 字符串 | 是 | 词条内容版本，建议用日期，形如 `2026.10.1` |
| `generated_by` | 字符串 | 是 | 取值 `builtin`、`generated`、`mixed`。标明该文件是否含机器生成内容 |
| `reviewed` | 布尔 | 否 | 默认 false。是否经过人工校对 |
| `entries` | 数组 | 是 | 词条列表 |

`generated_by` 与 `reviewed` 两个字段是**诚实性标记**。OQ-04 的建议答案是用人工智慧批量生成初始词典，此类内容必须能被区分出来，界面才能提示用户「这一批尚未人工校对」。

### 词条级字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `term` | 字符串 | 是 | 中文词，用户实际会输入的说法 |
| `tags` | 数组 | 是 | 目标标签及其权重，至少一项 |
| `aliases` | 字符串数组 | 否 | 同一词条的其他中文说法 |
| `exclude` | 字符串数组 | 否 | 需要排除的标签，用于「不要什么」这类表达 |
| `notes` | 字符串 | 否 | 给维护者看的说明，程序不使用 |
| `enabled` | 布尔 | 否 | 默认 true。置 false 可停用而不删除 |

`tags` 数组内每一项含两个字段。

| 字段 | 类型 | 说明 |
|---|---|---|
| `tag` | 字符串 | 目标标签，必须是来源站真实存在的标签 |
| `weight` | 实数 | 权重，取值 0 到 1，默认 1.0 |

**权重的含义是「这个词条对这个标签的支持强度」，不是标签在检索式中的布尔值。** 取 1.0 表示该标签是词条的主要含义，取较小值表示辅助含义。排序时按权重给匹配度加权，对应 DD-13 的标签匹配度维度。

权重不用于构造来源站的检索式。来源站无法表达权重，检索式里标签只有出现与不出现两种状态。因此实现上有两条派生规则。

1. **检索式只取权重最高的若干个标签**，具体个数由设置决定，默认 3。
2. 权重参与本地排序，让主要含义的图排在前面。

### 词条的唯一性

同一文件内 `term` 不得重复。程序加载时若发现重复，保留第一条并记录警告，不中断加载。

`aliases` 只是同一词条的书写变体，展开成独立查询入口，不与 `term` 冲突。若某个别名与另一个词条的 `term` 相同，以 `term` 为准并记录警告。

## 排除标签的用法

`exclude` 解决「要 A 不要 B」这类表达。

因此软件**不做否定语气的自然语言解析**。用户想排除某类内容时，界面提供显式的排除输入，其内容直接拼进检索式的负向部分。

`exclude` 字段只用于「这个词条天然容易带回某类结果」的固定修正。上文的示例中，「站姿」排除 `sitting` 与 `lying` 正是这一类：某些图同时打有 `standing` 与 `sitting` 两类标签，只请求 `standing` 并不能排除坐姿图。

界面须向用户展示最终检索式，对应设计原则「翻译结果必须可见、可改」。

## 与数据库的对应

加载词典文件时写入 `dictionary_entry` 表，字段对应关系如下。

| 文件字段 | 表字段 |
|---|---|
| `category` | `content_category_id`，由类别标识查出 |
| `term` | `term_zh` |
| `tags[].tag` | `tag` |
| `tags[].weight` | `weight` |
| `generated_by` | `source`，取值 `builtin`、`generated` 或 `manual` |
| `enabled` | `enabled` |
| `aliases` | 展开为多行，`tag` 与 `weight` 与主词条相同 |

`source` 列还允许取值 `user`，表示用户在程序内新增的条目。取值的完整集合为 `builtin`、`generated`、`manual`、`user`，由 `dictionary_entry` 表的 CHECK 约束限定。

**这是一处实际的坑。** 早期版本的 CHECK 约束漏了 `manual`，导致手工撰写的词典文件在加载时全部被拒。写入用的是 `INSERT OR IGNORE`，它把违反约束的行静默丢弃，计数却照加，于是报告显示「写入 12 行」而表内为 0 行。

因此实现了两条防呆措施：加载层遇到 `rowcount` 为 0 时重试一次不带 `IGNORE` 的插入，把真实原因暴露出来；词典文件新增取值时必须同步修改 CHECK 约束。

`aliases` 展开成多行而不是单独建表，理由是所有检索路径都按 `term_zh` 查，展开后查询逻辑统一。

## 加载与合并规则

程序启动时按下列顺序加载。

1. 读取 `manifest.json`，校验各文件的存在性与格式版本。
2. 逐个读取词典文件，写入 `dictionary_entry`。
3. 读取 `dictionary_override`，在内存中套用到已加载的条目上。

合并规则按覆盖动作分三种。

| 动作 | 效果 |
|---|---|
| `add` | 为某词条增加标签或别名 |
| `remove` | 删除某词条、某标签或某别名 |
| `replace` | 整体替换某词条的标签列表 |

**覆盖在内存中进行，不回写数据库的 `dictionary_entry` 表。** 理由是词典升级时会整体重建该表，若覆盖写进去会被一并冲掉。

## 翻译层的合成顺序

一次中文输入到标签组的完整处理顺序如下。

1. 输入规范化：全角转半角、去除多余空白、统一大小写。
2. 判断输入是否已经是标签格式。若是，跳过翻译直接进入检索，对应 OQ-12。
3. 按类别查词典，命中则产生标签候选。
4. 词典未命中或候选不足时，调用网络接口。接口结果写入 `translation_cache`，同一输入在缓存有效期内不重复请求。
5. 合并两路结果。词典命中项优先，接口只补充词典没有的标签。
6. 按权重排序，取前若干个标签构成检索式。
7. 把结果展示给用户修改。**这一步不可跳过。**

**词典优先于接口**，理由是词典的结果稳定、可解释、零成本，而接口的输出随机性较大。这条规则也保证了未配置接口时软件的功能完整。

## 版本与增量更新

`dictionary_version` 采用日期式版本号，形如 `2026.10.1`。

增量更新的做法是**替换整个文件而不是打补丁**。理由是词典文件体积很小，单个文件在数十 KB 量级，整体替换的实现与校验都更简单，也不会出现补丁叠加导致的难以复现的状态。

因此升级流程是：程序包内置新词典文件，启动时若发现版本号更高，重建 `dictionary_entry` 表。用户的覆盖不受影响。

`runtime_state` 表记录已加载的词典版本，避免每次启动都重建。

## 冷启动的构建流程（OQ-04 的建议答案）

OQ-04 给出的建议是「从图库标签体系反向构建」加「由人工智慧生成初始词典」的组合。落到具体流程上是四步。

1. **取标签。** 从 Danbooru 获取官方标签列表，含标签名、分类与使用次数。文档地址为 <https://danbooru.donmai.us/wiki_pages/help:api>。
2. **筛选高频标签。** 按使用次数排序，先覆盖人体姿势类的高频标签。理由是主用户明确表示人体姿势是主力需求。
3. **生成中文对应词。** 用接口批量生成中文说法，产出的文件 `generated_by` 标为 `generated`，`reviewed` 标为 false。生成时遵守一条约束：`tag` 必须是上一步取到的真实标签，程序在加载时校验，不存在的标签记录警告。
4. **人工校对。** 开发者逐条校对后把 `reviewed` 改为 true。校对的优先级是人体姿势类，然后是服装与道具，最后是场景建筑。

**这一步不能跳过的是第 4 步。** 翻译准确度是本项目的核心卖点，未经校对的生成内容直接作为默认词典会损害这一点。界面须提示用户当前词典中未校对词条的比例。

## 校验规则

程序加载词典时必须校验下列各项，发现问题记录警告而不中断启动，因为词典损坏不应导致软件不可用。

| 校验项 | 处理 |
|---|---|
| `schema_version` 高于程序支持的版本 | 跳过该文件，提示用户升级程序 |
| `category` 不在已知取值内 | 跳过该文件 |
| `term` 为空 | 跳过该词条 |
| `tags` 为空数组 | 跳过该词条 |
| `weight` 不在 0 到 1 之间 | 截断到区间内并记录警告 |
| `tag` 在来源站标签表中不存在 | 保留但记录警告，不删除，因为标签表可能不完整 |
| 同一文件内 `term` 重复 | 保留第一条 |
| `aliases` 与某词条的 `term` 冲突 | 以 `term` 为准 |

## 已知缺口

| 项 | 说明 |
|---|---|
| 词典实际规模 | 未实测。需要先取得标签列表才能给出预计词条数 |
| 中文别名的召回 | 同一意象的中文说法很多，如何保证覆盖，待校对阶段统计 |
| 日文输入 | 词典当前只收中文。OQ-12 已建议输入框接受任意语言，日文词条是否纳入待定 |
| 多人称与代词 | 例如「她」这类词应直接忽略，忽略词表尚未建立 |
| 权重的标定方法 | 权重目前靠人工判断。是否需要用检索结果反推权重，待第一期试用后决定 |
