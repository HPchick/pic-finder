# 主用户访谈实录

本文记录主用户（画师朋友）的原话，作为需求判断的一手依据。开发者负责提问与转述。

对应未决问题的编号在每段末尾标注。原始聊天截图不随文档保存，如需追溯请联系开发者。

## 第一次访谈：用途与设备

### 关于参考图的用途

开发者提问：你主要的找参考图的真实用途主要是哪种。

主用户回答：我一般是第一种。

开发者补充说明：第一种指为了作画，即找姿势、人体、构图、透视参考。

主用户补充回答：灵感的话，我一般是脑子里有东西但是画不出来。然后听歌和看文案啥的会有，一般不会专门找。

主用户补充回答：单纯好看的图的话，我一般是用微博，有一个专门的号关注画师，然后微博他也会有推荐相关的博主，想起来可能会去存，比较方便。

**转述与解读**

这一段做了三段定位。

- 检索参考图的目的是作画，不是灵感，也不是收集好看的图。
- 灵感不通过检索获得，来源是听歌与看文案。
- 收集好看的图不通过检索获得，渠道是微博小号关注画师，依靠平台的推荐流。

由此可以确认一点：本软件不应承担发现好看的图这一职责，那属于微博的能力范围。

同时出现一个待澄清的关键表述：脑子里有东西但是画不出来。该问题在第二次访谈中得到部分解答，即她的检索目标按用途分为四类。

### 关于绘图设备

开发者提问：你一般用什么设备画画。

主用户回答：我一般是 iPad。

主用户补充回答：之前没有 iPad 就是电脑。

**转述与解读**

主用户的绘图主力设备是 iPad，电脑是备选。这与本软件面向 Windows 桌面的定位存在落差，见 OQ-14。

### 关于电脑配置

开发者提问：方便说下什么电脑吗。

主用户回答：我的是拯救者。

主用户补充回答：具体型号我给你看眼。

主用户提供的截图显示：拯救者 Y7000P，32 GB 内存，1 TB 硬盘，5060 显卡。

**转述与解读**

该配置具备本地运行中等规模模型的能力，与开发者此前"绘画电脑性能较弱"的描述不符，见 OQ-15。

## 第二次访谈：参考图的分类

### 关于分类方式

开发者先说明自己的设想：我找网站的时候主要有人体姿势，服装道具素材，和主要偏场景建筑的，我在想要不要全部聚合到一起。

主用户回答：我一般是主要是人体姿势。

主用户补充回答：如果涉及到人物拿武器的话可能会用到道具。

主用户补充回答：服装我一般是和姿势分开来找。

主用户补充回答：我觉得这个分类来做比较好。

开发者追问：这个分类具体指哪几类。

主用户回答：人体姿势一类，服装一类，道具一类，场景建筑一类，将服装和道具分开可以提高搜索效率。

开发者追问：动漫成品图是否需要单独一类。

主用户回答：动漫图同样按照前一个问题我给出的四类分类，不需要特别区分。

**转述与解读**

这一段给出了产品的分类骨架与三条设计结论。

**分类骨架。** 参考图的一级分类为四类：人体姿势、服装、道具、场景建筑。这四类由主用户本人给出并认可。

**结论一：服装与道具必须分开。** 主用户指出，分开可以提高检索效率。原因是这两类在检索时的目标不同，混在一起会互相干扰。因此界面不能把它们合并为一个入口。

**结论二：动漫图不单列。** 动漫成品图不是独立类别，而是这四类各自的检索来源之一。也就是说，同一类别下可以同时有真人素材与二次元成品图。

**结论三：全部聚合指的是类别内部聚合。** 开发者的原始设想是"要不要全部聚合到一起"。结合主用户的两次回答，聚合的作用范围是每一类内部的多个网站，而不是把四类的结果混在同一屏。

**优先级。** 主用户明确表示主要是人体姿势，道具属于条件触发，例如人物持武器时。场景建筑类由开发者提出，主用户未否认。
