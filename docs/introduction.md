# 简介

本文介绍 PIC FINDER 的定位、功能范围与使用流程。软件的详细设计理由见《设计决策记录》。

## 软件定位

PIC FINDER 是一个参考图检索与归档工具。它把中文意象翻译成图库标签，跨站检索参考图，并把下载的图片自动归档。

它要解决的不是检索本身。画师本来就会用浏览器搜图。它要解决的是下面三件事。

- 图库只认英文或日文标签，画师想不出该搜什么词。本软件负责翻译，并把翻译结果展示出来供用户修改。
- 画师要在多个网站分别搜一遍。本软件提供一个输入框，跨站并发检索，结果汇总在一屏。
- 存下来的参考图文件名混乱，过一阵就找不到。本软件下载即归档，本地图库可检索、可筛选。

## 目标用户

主用户是一位画师。她不是技术人员，不装环境、不改配置、不读日志。

她已完成两轮访谈，需求依据见 [interviews.md](interviews.md)。

她的绘画电脑为拯救者 Y7000P，配置 32 GB 内存、1 TB 硬盘与 5060 显卡，可以承担中等规模的本地模型推理。本地大语言模型推理仍然不做，理由是成本与复杂度，不是性能，见 DD-04。

本地图像标注模型允许使用且默认关闭，见 DD-17。人工智慧能力优先通过网络接口提供。未配置接口时，软件必须保持完整可用。

尚未访谈的部分是界面操作习惯与参考图流转方式，见 OQ-02 与 OQ-14。这两项是当前最大的需求风险。

## 两条设计原则

**翻译结果必须可见、可改。** 软件不能把中文到标签的翻译当作黑盒。用户必须能看到软件的理解结果，并在搜错时当场修改标签重新检索。

**自动做的事必须能被推翻。** 自动归档、自动分类、自动去重都属于软件替用户做的判断。每一项都必须有可见的结果、可撤销的路径，并且出错时不破坏原有数据。

还有第三条原则针对开发者：不确定的东西不做。凡是涉及审美判断的功能，默认关闭，要做也必须由用户显式开启。

| F-06 | 结果图墙 | 缩略图网格，可查看大图，可跳转原帖 |
| F-07 | 勾选下载 | 支持多选批量下载，有进度与结果反馈 |
| F-08 | 自动归档 | 按用户选定的规则建立目录并落盘 |
| F-09 | 本地图库检索 | 已下载图片可按标签、画师、来源站、尺寸、时间筛选 |

| F-15 | 参考图类别切换 | 检索页提供人体姿势、服装、道具、场景建筑四类入口，各类独立保存检索条件与结果，见 DD-18 |

### 第二期功能

第二期实现以图找源，详见《设计决策记录》的 DD-02。

| 编号 | 功能 | 验收标准 |
|---|---|---|

### 延后功能

下列功能明确延后，但数据结构须预留支持。

- 扩展分类维度：按日期、按尺寸、按标签组合自动分目录。
- 用户自定义分类：用户自行定义文件夹规则，例如按氛围手工归档。
- 人工智慧视觉分类：由用户显式开启，且只给建议，不自动移动文件。
- 收藏夹与灵感板：跨来源组织图片，例如按项目分组。
- 检索历史：记录并回看以往的检索。

## 检索流程

一次完整的文字检索经过六层处理。

1. 用户选择参考图的类别：人体姿势、服装、道具或场景建筑。
2. 用户输入中文描述。
3. 翻译层调用接口或本地词典，产生标签候选。
4. 用户确认或修改标签。这一步不可跳过。
5. 检索层并发请求该类别下启用站点的接口，每站独立限速。
6. 归一化层统一字段，合并层去重，排序层排序，界面呈现图墙。

用户勾选结果后，进入下载与归档流程。

## 下载与归档

### 任务状态

下载任务按下列状态迁移：排队中、下载中、成功、已归档、已入库。

失败的任务进入待处理状态，在界面标红，可以重试。批量下载中单张失败不得中断整批。

### 归档规则

软件内置两类归档维度，可以组合，也可以全部关闭。

| 规则 | 目录示例 | 可靠性 |
|---|---|---|
| 按来源站 | `danbooru/`、`safebooru/` | 完全可靠，元数据直接可得 |
| 按画师 | `danbooru/artist-name/` | 可靠，画师名须净化特殊字符 |
| 按日期 | `2026-02/` | 完全可靠 |
| 按尺寸档 | `large/`、`medium/` | 完全可靠 |
| 按检索主题 | `red-cloak/` | 完全可靠，但目录容易碎片化 |
| 按站内标签 | `1girl/` | 一般，多标签时需规定取前几项 |
| 不归档 | `library/` | 全部平铺 |

DD-18 要求归档目录预留参考图类别的维度，即人体姿势、服装、道具与场景建筑。该维度尚未写入本表，已登记为未决问题 OQ-19。

归档须遵守四条约束。

1. 只作用于新下载的图片，不移动、不重命名用户已有的文件。
2. 文件名必须可读，格式为站点、作品编号、画师、序号的组合。
3. 文件名必须净化 Windows 非法字符，并截断到路径长度限制以内。
4. 下载前先查库，已存在的作品跳过并提示。

## 排序策略

排序支持四个维度。界面只提供单维度一键切换，不提供多滑块权重调节。

| 维度 | 默认权重 | 说明 |
|---|---|---|
| 标签匹配度 | 40% | 按命中标签数与标签权重计算 |
| 人气 | 30% | 各站字段不同，须归一化 |
| 分辨率 | 20% | 按总像素数计算，避免被长宽比误导 |
| 时间 | 10% | 越新得分越高 |

默认权重只是初值。用户切换到单维度排序时，软件必须完全按该维度排序，不得混入其他维度。

## 数据存储

### 目录结构

```
pic-finder/                  安装目录，用户可选，默认非系统盘
├── PicFinder.exe            主程序
├── _internal/               打包依赖
├── data/                    程序数据，可改到别处
│   ├── config.json          用户设置
│   ├── library.db           图库索引数据库
│   ├── dictionary/          中文到标签的词典
│   ├── cache/               缩略图与检索缓存
│   └── logs/                运行日志
└── library/                 默认图库根目录，可改到别处
    ├── danbooru/
    └── _pending/            下载失败或无法归档的图片
```

### 数据分类

数据分三类，生命周期各不相同。

| 类别 | 示例 | 升级时 | 卸载时 | 可否删除 |
|---|---|---|---|---|
| 程序文件 | 可执行文件、依赖 | 被覆盖 | 删除 | 不可以 |
| 可再生数据 | 缓存、缩略图 | 可覆盖 | 删除 | 可以，会重新生成 |
| 不可再生数据 | 配置、索引库、图片库 | 必须保留 | 须明确询问 | 不可以 |

升级流程必须做到只替换程序文件，绝不触碰 `data/` 与 `library/` 两个目录。

### 配置导出

配置导出文件名为 `picfinder.profile.json`。它包含设置、归档规则、收藏夹与词典覆盖项。

导出时默认不包含接口密钥。若要包含，界面须给出明确警告。这个机制用于应对升级覆盖或数据目录无法读取的情况。

## 界面分区

界面分三个顶层页面，任何功能不超过两层。检索页内部再按参考图的四类划分入口。

**检索页**：四个类别入口、大输入框、可编辑的标签条、成人内容开关、来源筛选、排序与筛选控件、结果图墙、可收起的下载队列面板。

**图库页**：本地已下载图片的浏览、检索、筛选与统计。支持按类别筛选，支持按分级筛选。

**设置页**：数据与存储、搜索来源、翻译接口、归档规则、关于。设置项按内容分类分组，不按重要程度排序。

检索页的布局如下。

```
┌──────────────────────────────────────────────────────┐
│  [ 检索 ]        [ 图库 ]        [ 设置 ]             │
├──────────────────────────────────────────────────────┤
│  类别：[人体姿势] 服装   道具   场景建筑               │
├──────────────────────────────────────────────────────┤
│  ✎ 描述你需要的参考                          [搜索]   │
├──────────────────────────────────────────────────────┤
│  翻译结果：1girl ✕  standing ✕  holding ✕  + 添加     │
│  来源：[✓] 站点甲  [✓] 站点乙  [ ] 站点丙             │
│  排序：[匹配度▾]   分辨率：[不限▾]                    │
│  分级：[ ] 包含 R18 内容  ← 显眼位置，默认不勾选        │
├──────────────────────────────────────────────────────┤
│  ▣ ▣ ▣ ▣ ▣ ▣                                          │
│  ▣ ▣ ▣ ▣ ▣ ▣            [下载所选 (3)]                │
└──────────────────────────────────────────────────────┘
```

四个类别各自独立保存检索条件与结果。切换类别时，输入框内容随之切换，不与上一类混合。

分级控件的位置与默认值由 DD-21 决定。它是一个复选框，不是下拉菜单，因为档位只有两个。它必须常驻可见，不藏进设置页，默认不勾选，从关闭切到开启时需要一次确认。

| 控件状态 | 请求的分级 |
|---|---|
| 不勾选（默认） | `general`、`sensitive` |
| 勾选 | 四档全含 |

**不勾选时必须同时请求 `general` 与 `sensitive` 两个值。** 只请求 `general` 会把泳装与贴身衣物类参考一并排除，而这一类在服装类参考里是正当需求。

Danbooru 系的写法必须是简写形式 `rating:g,s`。已实测确认，两项分开写成 `rating:general rating:sensitive` 会返回 0 条，因为同前缀的两次限定取交集而不是并集。实测记录见 [feasibility.md](feasibility.md)。

界面须遵守五条约束。

1. 顶层只有三页，功能层级最多两层。
2. 类别入口位于检索页内部，不构成第四层界面。
3. 危险操作需要二次确认，并说明后果。
4. 下载队列是浮动面板，不占用独立页面。
5. 分级控件常驻检索页可见区域，是一个复选框，默认不勾选，开启时需要一次确认。理由见 DD-21。

## 非功能需求

| 编号 | 需求 | 指标 |
|---|---|---|
| N-01 | 冷启动速度 | 打包后实机测量不超过 3 s。开发者已主观确认启动很快；精确数值待补测 |

**N-01 的补充说明。** 首次测量的脚本存在缺陷，取到的是无效值。缺陷有两条：使用了 `firstFrameSwapped` 事件计数而没有兜底，事件不触发时写入空值；以及计时从 Python 进程内部开始，漏掉了进程创建与动态库加载这一段真正影响用户感知的时间。

口径已修正为「从进程创建到窗口出现」的外部计时。开发者随后判断启动速度很快，暂不需要精确数值。因此 N-01 记为开发者主观确认达标，精确数值待交付前补齐。
| N-02 | 首屏可用 | 打开即可输入，不等待网络请求 |
| N-03 | 离线可用性 | 无网络时不崩溃；本地图库功能不受影响 |
| N-04 | 并发与限速 | 每站独立限速；Danbooru 长会话控制在 1 req/s 以内 |
| N-05 | 用户代理标识 | 使用可识别的自定义标识，禁止冒充浏览器 |
| N-06 | 磁盘占用 | 缓存可一键清理；统计页显示各类占用 |
| N-07 | 打包体积 | 不设硬性上限，见 DD-20。交付前实测标准版与完整版的目录体积并如实标注 |
| N-08 | 权限 | 安装之外不需要管理员权限 |
| N-09 | 数据安全 | 任何自动操作不得删除用户已下载的图片 |
| N-10 | 可排错 | 有日志文件，可一键导出用于求助 |

**N-07 的实测值。** 2026-10-07 测得：程序目录 124.8 MB，共 227 个文件；安装程序 37.2 MB；便携压缩包 51.6 MB。构成以 Qt 运行库与 Python 运行时为主，内置词典与十万条中文标签表合计约 9.6 MB。完整版内置标注模型之后的体积未测，见 DD-19。

**N-08 已实测。** 安装程序不请求提权，普通账户即可装完，默认装到用户目录。装完之后程序目录可写，数据因此可以放在程序旁边。见 DD-25。
